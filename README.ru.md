## Собственный локальный S3-сервер

`make start-s3` запускает сам Files как S3-сервер на `http://127.0.0.1:3062`. Режим `FILES_ROLE=s3` использует один процесс и постоянный том `/data/s3`, без PostgreSQL, worker и облачного хранилища. Независимые случайные ключи создаются в `.env.native-s3`; существующий `.env` сохраняется. `make stop-s3` останавливает сервер с сохранением данных; `make logs-s3` показывает логи.

Обычному S3-клиенту нужны endpoint выше, region `us-east-1`, path-style и `FILES_S3_ACCESS_KEY_ID` / `FILES_S3_SECRET_ACCESS_KEY` из `.env.native-s3`. Поддерживаются SigV4, подписанные ссылки, операции с бакетами и объектами, копирование, списки, multipart. Полное совпадение со всеми возможностями AWS/Яндекса не заявляется: IAM, ACL, versioning, lifecycle, шифрование на стороне сервера и репликация не реализованы. Каталог данных обслуживает только один процесс. Ограничение объекта по умолчанию — 10 000 000 000 байт.

`make smoke-s3` проверяет совместимость обычного клиента на временных данных. Старый Adobe S3Mock запускается через `make start-s3mock`. REST API `/api/v1/files` и его политики остаются отдельным режимом; native S3 хранит произвольные байты без проверки медиа и тарифов.

## S3-совместимые хранилища

S3 означает **Simple Storage Service**, а не третью версию API. Amazon S3 — сервис AWS; Selectel и Yandex Object Storage предоставляют совместимые API. Яндекс Диск — другой продукт с OAuth API. Формат Files `/api/v1/files` остаётся единым, как и авторизация, проверка файлов, PostgreSQL и очередь удаления.

Провайдеры: `yandex` — Яндекс Диск; `simulator` — файловая система; `selectel` — S3 Selectel; `aws` — Amazon S3; `yandex-object` — Yandex Object Storage; `s3` — другой совместимый endpoint или локальный стенд.

В `.env` задайте `STORAGE_PROVIDER`, `S3_BUCKET`, `S3_REGION`, `S3_ENDPOINT`, `S3_ACCESS_KEY_ID` и `S3_SECRET_ACCESS_KEY`, затем выполните `make start`. Endpoint и регион/пул Selectel берутся из панели провайдера. Для Yandex Object Storage: `https://storage.yandexcloud.net`, регион `ru-central1`. Для AWS endpoint необязателен; без явных ключей используется стандартная цепочка credentials SDK, которой отдельно нужно предоставить доступ внутри контейнера. `S3_SESSION_TOKEN` — временные credentials; `S3_FORCE_PATH_STYLE=true` — адресация по пути; `false` — virtual-hosted. Префикс объектов: `S3_KEY_PREFIX=timepost/`. Облачные адреса требуют HTTPS, ключи остаются на сервере.

Создайте отдельный приватный бакет **без включённой или приостановленной истории версий**. Проверка готовности отклоняет versioning: удаление по ключу иначе не гарантирует удаления старых версий. Нужны права HeadBucket, GetBucketVersioning, PutObject, GetObject и DeleteObject. Облачные бакеты автоматически не создаются. Подмена облака локальным хранилищем не выполняется. Смена бакета, префикса или endpoint не переносит байты: используйте отдельную БД/экземпляр либо проверенную миграцию данных.

### Локальная проверка S3

Yandex Object Storage поддерживает `YANDEX_IAM_TOKEN` вместо S3-ключей (не смешивать режимы). Для `yandex-object` endpoint и регион по умолчанию — `https://storage.yandexcloud.net` и `ru-central1`. IAM-токен действует не более 12 часов: получить новый токен и пересоздать API и worker до истечения; автоматического обновления нет. AWS использует SigV4. Наш `/api/v1/files` — API Timepost, а не готовая замена S3-сервера. Область совместимости и настройки: [отчёт](../archive/docs/reports/2026-10-03-files-s3-compatibility.md). [Авторизация Яндекса](https://yandex.cloud/ru/docs/storage/api-ref/authentication).

```sh
make start-s3mock
make smoke-s3mock
make logs-s3mock
make stop-s3mock
```

UI: `http://127.0.0.1:3060` (либо `FILES_PORT` из `.env`). Все провайдеры используют один Compose-проект `timepost-files-standalone`, один API, PostgreSQL и worker удаления. `make start-s3mock` выбирает локальный S3 в общем `.env`, сохраняя ключи Files, пароль БД и порт; эмулятор Adobe S3Mock и инициализация bucket добавляются в тот же проект. `make start`, `stop`, `ps`, `logs` и `smoke` автоматически учитывают текущего провайдера. Команды проверки `*-s3mock` — совместимые алиасы, а не дополнительные установки. Настроенное облачное хранилище команда `start-s3mock` не перезаписывает.

Ключи S3 используются только сервером. Порт S3Mock наружу не опубликован. Это тестовый эмулятор, не production-хранилище и не проверка реальных IAM/подписей. Остановка сохраняет тома. Для возврата к файловому симулятору установите `STORAGE_PROVIDER=simulator` в `.env` и выполните `make start`. Метаданные сохраняются в общей БД; списки ограничены выбранным провайдером. Смена провайдера не переносит байты и не меняет провайдера существующих файлов. Изменение bucket/endpoint/prefix существующего S3 требует проверенной миграции.

Ранние установки использовали `timepost-files-s3`, порт 3061 и `.env.s3`. Это устаревший отдельный запуск: остановите его командой `docker compose --env-file .env.s3 -p timepost-files-s3 -f compose.yaml -f compose.s3.yaml down` **без `--volumes`**. Сохраните конфигурацию и тома для восстановления; старые данные автоматически не импортируются. Новые команды второй проект не создают.

Источники: [AWS](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html), [Selectel](https://docs.selectel.ru/api/object-storage-s3/), [Yandex Object Storage](https://yandex.cloud/ru/docs/storage/s3/), [Adobe S3Mock](https://github.com/adobe/S3Mock). Реальный облачный прогон без credentials не выполнен.

## Автономный запуск

В каталоге `files/` выполните `make start`. Команда создаёт `.env` с отдельными
случайными ключами и паролем БД, затем собирает Docker-контейнеры и ждёт готовности.
Повторный запуск сохраняет настройки и тома. Из корня Timepost:
`make files-standalone`; резервный вход: `make -f scripts/main/Makefile files-standalone`.

Для запуска вместе с Timepost из корня workspace: `make dev-file` (локальные frontend разработки) или `make start-file` (Docker-сборка и запуск). Сначала собирается и запускается автономный Files, затем обычный режим Timepost. После готовности открываются Timepost, Admin и Files; `OPEN_BROWSER=false` отключает открытие. Команды доступны и через `make -f scripts/main/Makefile`. У автономного Files отдельные данные и ключи; он пересобирается при повторном запуске команды, без hot reload. Для другого порта: `FILES_PORT=4060 FILES_UI_URL=http://127.0.0.1:4060`. Остановка автономных контейнеров из workspace: `make -C files stop`.
Для отдельного использования достаточно каталога `files/`, Docker Compose и Node.js 24
для подготовки окружения; соседние проекты не требуются.

Интерфейс: <http://127.0.0.1:3060>. Введите `FILES_API_KEY` из локального `.env`,
выберите числовой ID пространства и подключитесь. Доступны список с догрузкой,
загрузка, скачивание и постановка удаления в очередь. Ключ хранится только в памяти
страницы. `FILES_READONLY_API_KEY` разрешает чтение без загрузки и удаления.
Оба ключа относятся ко всему экземпляру, включая все пространства: это сервисные
ключи, а не многопользовательская модель прав. Порт опубликован только на loopback.
OAuth-токен в браузер не передаётся. Не публикуйте `.env`.

`make smoke` проверяет только симулятор и удаляет собственные тестовые файлы.
Из корня: `make files-smoke`. `make ps`, `make logs`, `make stop` — управление
контейнерами; остановка сохраняет данные. `make config` проверяет Compose без вывода секретов.

### Как получить и заменить ключ доступа

1. В каталоге `files/` выполните `make setup`: при первом запуске создаётся приватный `.env` со случайными ключами. Существующий файл не перезаписывается.
2. Откройте `.env` локально. Значение `FILES_API_KEY` вставьте в поле «Ключ доступа» UI. `FILES_READONLY_API_KEY` подходит для просмотра и скачивания без записи.
3. В HTTP-клиенте передавайте `Authorization: Bearer <ключ Files>`. Ключи `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` относятся к хранилищу и сюда не подходят.

Чтобы создать новый тестовый ключ, выполните:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Скопируйте результат в `FILES_API_KEY` или `FILES_READONLY_API_KEY` своего `.env`, затем выполните `make start`. Для двух полей генерируйте разные значения; сервис требует минимум 32 символа. Старый заменённый ключ перестанет работать после пересоздания API. `make setup` ключи не вращает. Не изменяйте `FILES_DB_PASSWORD` при этой операции.

Сейчас экземпляр принимает один полный и один readonly-ключ, общие для всех пространств. Регистрации клиентов и выдачи множества независимых клиентских ключей нет. Для пользовательских прав используйте режим Timepost с Accounts/Projects. Не публикуйте `.env`, не добавляйте ключи в Git или URL и не вставляйте облачные credentials в браузер.

## Яндекс Диск

В `files/.env` задайте `STORAGE_PROVIDER=yandex` и `YANDEX_DISK_OAUTH_TOKEN`,
затем повторите `make start`. Токен должен разрешать работу с папкой приложения
`app:/timepost`: [официальная документация REST API и OAuth](https://yandex.ru/dev/disk/rest/).
Метаданные остаются в PostgreSQL, байты записываются на Диск. При ошибке облака
сервис не переключается на симулятор. Файлы другого провайдера скрываются из списка;
метаданные и скачивание по их ID возвращают ошибку несовпадения провайдера.
Подключение личного Диска каждым пользователем и Google Drive не реализованы.
Реальный облачный прогон требует действующего токена и пока не подтверждён.

## API и жизненный цикл

Контракт: [openapi.json](openapi.json); YAML для Timepost: [openapi.yaml](openapi.yaml).
Автономная генерация: `npm run openapi:generate`; проверка: `npm run openapi:check`.
HTTP Swagger не открывается. Контракт Files описывает собственный REST API,
а не GraphQL и не точную копию внешнего API Яндекс Диска.

В корне workspace `make api-sync` обновляет исходные контракты и snapshots для
потребителей; `make api-check` сверяет их с кодом и запускает OpenAPI-линтер.
`make api-docs` — отдельный ручной экспорт: после проверки создаёт HTML с
навигацией, соседние JSON/YAML и ZIP в `archive/docs/`. В частности,
`archive/docs/api/index.html` открывает пакет документации всех сервисов.
Эти файлы не обслуживают экран фронтенда и не нужны для запуска Files.
Обычные `make dev`, `make seed` и `make api-sync` этот HTML-пакет не пересобирают.

Зависимость Redocly для общего экспорта находится в `scripts/package.json`,
а не в приложении Timepost. `files/public/index.html` — самостоятельный интерфейс
загрузки и просмотра файлов, а `archive/docs/api/files.html` — генерируемая
справка API. Это разные страницы с разными потребителями. Источники:
[общий генератор контрактов](../scripts/openapi-contracts.mjs),
[генератор HTML/ZIP](../scripts/openapi-handoff.mjs).

- `POST /api/v1/files?projectId=1&fileName=photo.png`: сырые байты тела, Bearer-ключ.
- `GET /api/v1/files?projectId=1&limit=20&cursor=UUID`: список готовых файлов, курсорная пагинация.
- `GET /api/v1/files/{id}` и `GET /api/v1/files/{id}/content`: метаданные и приватное содержимое.
- `DELETE /api/v1/files/{id}`: HTTP 202, долговечное задание удаления.
- `GET /api/v1/files/{id}/deletion`: состояние задания и число попыток, также после удаления.
- `GET /api/v1/storage`: безопасные сведения о режиме и возможностях; `GET /health/ready`: готовность.

Фото и произвольные файлы: 10 MiB (10 × 1024 × 1024 байт).
Видео: 100 MiB (100 × 1024 × 1024 байт). JPEG/PNG/WebP проверяются декодером:
один кадр, не более 4096 × 4096 пикселей. MP4 H.264/AAC и WebM VP8/VP9 с
Opus/Vorbis проверяются через ffprobe: один видеопоток, не более одного аудиопотока,
до 4096 × 4096 и 60 минут. Длительность возвращается как `durationSeconds`.
HEIC, AVI, MOV, транскодирование, извлечение обложек и полный прогон декодера видео
пока не реализованы. Видео скачивается с авторизацией как Blob и показывается
существующим видеоплеером; API поддерживает один byte-range; возобновляемая загрузка отсутствует.
Прочие байты в автономном режиме сохраняются
как `application/octet-stream` и скачиваются вложением; проверка антивирусом отсутствует.
Размер и SHA-256 проверяются при выдаче. Загрузка становится `ready` после подтверждения
провайдера. Незавершённые `pending` старше суток ставятся на очистку worker.

Удаление проходит `deleting` → `deleted`; задания — `pending` → `running` → `done`
либо повтор/`failed`. PostgreSQL хранит очередь, lease на 120 секунд и повторные попытки;
после 10 обработанных неудач задание останавливается. Повторный DELETE возобновляет
остановленное задание. Метаданные удалённого файла сохраняются для аудита.
Redis, Kafka и RabbitMQ для этой очереди не требуются. Миграции применяются API
последовательно под блокировкой БД. Резервные копии томов и облака настраиваются отдельно.

## Подключение Timepost

Обычные `make start`, `make dev` (он вызывает `dev-local`), `make dev-docker`, `make dev-local` включают Files.
`make files-start` запускает только Files и его зависимости. В общем стеке по
умолчанию используется симулятор с Accounts-сессиями и проверкой прав через Projects.
Для Яндекс Диска задайте в корневом `.env` `FILES_STORAGE_PROVIDER=yandex` и
`YANDEX_DISK_OAUTH_TOKEN`; облачный режим требует действующего OAuth.
Фронтенд использует `/api/files-service`, Posts проверяет `mediaFileId` через Files.
Удаление защищает привязанные и старые неучтённые файлы; правила описаны ниже.
Это отдельный запуск: автономные сервисные ключи не заменяют пользовательские права Timepost.

При `make dev` подготовка данных уже вызывается автоматически. `make seed` добавляет
недостающие демонстрационные записи Accounts/Projects/Posts/Notifications и справочник
Analytics; это не сброс существующей БД. Files не создаёт вымышленных файлов из seed:
байты появляются после успешного upload API. Перезапуск и seed не очищают тома Files.

Путь данных редактора: браузер → `/api/files-service/api/v1/files` → Files → провайдер.
После загрузки браузер отправляет в Posts JSON с `mediaFileId`. Posts проверяет
метаданные файла по пользовательской сессии и сохраняет тип `image`/`video`, размеры
и ссылку. При повторном открытии редактора сохранённый ID возвращается, повторная
загрузка того же медиа не требуется. Reels и Stories используют тот же файл; это
не подтверждение доставки в социальную сеть.

Фотографии аватаров и обложек технически можно хранить как изображения проекта.
Сохранение ссылки в Accounts/Projects — отдельный контракт владельца этих данных;
автоматическая интеграция всех аватаров, обложек и вложений чатов пока не реализована.

## Примеры для автономного API

Ключ экспортируйте локально из своего `.env`, не вставляйте его в документацию.
В Timepost вместо сервисного ключа используется пользовательский Bearer-токен.

```sh
# Загрузить фотографию; ответ содержит data.mediaFileId.
curl --fail-with-body -H "Authorization: Bearer $FILES_API_KEY" \
  -H 'Content-Type: image/jpeg' --data-binary @photo.jpg \
  'http://127.0.0.1:3060/api/v1/files?projectId=1&fileName=photo.jpg'

# Аналогично загрузить MP4: замените MIME на video/mp4 и путь файла.
curl --fail-with-body -H "Authorization: Bearer $FILES_API_KEY" \
  'http://127.0.0.1:3060/api/v1/files?projectId=1&limit=20'

# Подставьте UUID из ответа загрузки.
curl --fail-with-body -H "Authorization: Bearer $FILES_API_KEY" \
  "http://127.0.0.1:3060/api/v1/files/$FILE_ID/content" --output saved-file
curl --fail-with-body -X DELETE -H "Authorization: Bearer $FILES_API_KEY" \
  "http://127.0.0.1:3060/api/v1/files/$FILE_ID"
curl --fail-with-body -H "Authorization: Bearer $FILES_API_KEY" \
  "http://127.0.0.1:3060/api/v1/files/$FILE_ID/deletion"
```

## Связь с API Яндекс Диска

Внешний контракт Files остаётся одинаковым для обоих провайдеров. Яндекс-адаптер
работает с настоящими REST-операциями Диска; симулятор реализует тот же интерфейс
`ready/upload/download/delete` локально. Это не HTTP-клон API Диска.

| Операция Files | Адаптер Яндекс Диска                                     | Симулятор                   |
| -------------- | -------------------------------------------------------- | --------------------------- |
| Подготовка     | Создание `app:/timepost` через `PUT /resources`          | Подготовка каталога         |
| Upload         | Получение адреса `/resources/upload`, затем бинарный PUT | Запись UUID-файла и sync    |
| Content        | Получение адреса `/resources/download`, затем GET        | Чтение UUID-файла           |
| Delete         | `DELETE /resources` с `permanently=true`                 | Удаление UUID-файла         |
| List/metadata  | Метаданные PostgreSQL нашего сервиса                     | Те же метаданные PostgreSQL |

OAuth передаётся только API Диска. Временные адреса не возвращаются браузеру;
проверяется HTTPS и домен, редиректы запрещены. HTTP 202 от облачного провайдера
не выдаётся как завершённая загрузка; незавершённая операция остаётся pending.
Основание: [адаптер](src/modules/files/infrastructure/storage/yandex-disk-storage.ts) и
[официальная документация Яндекса](https://yandex.ru/dev/disk/rest/).
Для изучения форматов запросов и ответов используйте
[введение в REST API Диска](https://yandex.ru/dev/disk-api/doc/ru/);
для получения токена —
[регистрацию приложения OAuth](https://www.yandex.ru/dev/id/doc/ru/register-client).
Эти ссылки проверены 2 октября 2026 года. Наличие адаптера в коде не заменяет
проверку реальных облачных запросов с действующим токеном.

## Собственный сервер

Для хранения на своём сервере используйте явный `simulator`: его файловый адаптер
записывает реальные байты в постоянный volume `objects`, а метаданные — в `metadata`.
Название режима обозначает локальную альтернативу облаку, а не фиктивные ответы.
Сервис с этим адаптером можно запускать и на сервере. Настройте резервное копирование
обоих томов, HTTPS reverse proxy и отдельные сервисные ключи; наружу не публикуйте БД.
Compose по умолчанию оставляет HTTP-порт на loopback. Регистрация пользователей
не дублируется: автономно используются ключи, в Timepost — Accounts.

Переключение `simulator` ↔ `yandex` меняет провайдер новых загрузок, а не переносит
байты. Каждая запись хранит своего провайдера: ранее загруженные файлы другого
провайдера не выдаются. Для переноса нужна отдельная процедура копирования с
проверкой checksum и обновлением метаданных; такая миграция ещё не реализована.

Для запуска без Docker необходимы PostgreSQL, Node.js 24 и ffprobe в PATH:
`npm ci`, настройки из `.env.example`, затем `npm run build` и `npm start`;
для отдельного worker — `FILES_ROLE=worker npm start`. Переменные должны быть экспортированы
в окружение процессов; сам Node не читает `.env` автоматически.

Проверки: `npm ci`, `npm run typecheck`, `npm test`, `npm run lint`, `npm run format:check`.

## Архитектура модулей

```text
src/
  app/                         настройка зависимостей и запуск API/worker
  modules/
    files/
      domain/                  модель файла, статусы и ограничения
      application/             сценарии работы с файлами и удаления
        ports/                 контракты репозитория, хранения, проверки медиа и идентификаторов
      infrastructure/          PostgreSQL, Яндекс Диск, локальное хранение, sharp/ffprobe
      presentation/            HTTP, DTO и OpenAPI
      contracts.ts             публичные типы модуля
    access/
      application/             контракт авторизации и доступа к проекту
      infrastructure/          Accounts/Projects JWT и автономные API key
      contracts.ts             публичные типы доступа
  shared/                      общие ошибки, guards и инфраструктурные типы
  server.ts                    стабильная точка запуска
```

`FileService` получает интерфейсы через конструктор. Прикладные ошибки
имеют отдельный тип кода; HTTP-статусы определяет транспорт. Проверка медиа и создание
UUID/checksum реализованы адаптерами; приложение использует `Uint8Array` и
`AsyncIterable`, не зависит от `sharp`, PostgreSQL и HTTP `Response`.
Сборка зависимостей находится в `app/create-file-service.ts` и `app/bootstrap.ts`.

Типы домена живут в `modules/files/domain/file.ts`, порты — в `application/ports`,
HTTP DTO — в `presentation/http/file-dto.ts`. Последние также переиспользуются
в исходнике UI через `import type`. Внешние адаптеры могут импортировать публичные
типы через `modules/files/contracts.ts` и `modules/access/contracts.ts`.
Общий файл `types.ts` заменён этими контрактами.

`test/architecture.test.ts` проверяет направление зависимостей: domain
не импортирует внешние слои, application не импортирует инфраструктуру/HTTP,
а другой feature module доступен через его публичные контракты.
Во время сборки очищается только генерируемый каталог `dist`, чтобы старые
скомпилированные модули после переноса не попадали в runtime.

## Ссылки, миниатюры и диапазоны

Posts регистрирует постоянную ссылку `post:<id>` через внутренний `POST /api/v1/internal/file-references` с `{projectId, referenceId, fileIds, cleanupRemoved}`. Нужен HS256 system JWT: `serviceId=posts-service`, `files:references:write`, настроенные issuer/audience. Сессии пользователей и автономные ключи не подходят. Только готовые файлы того же проекта; блокировки сериализуют привязку и удаление.

После commit окончательного удаления освобождаются ссылки: `fileIds: []`, `cleanupRemoved: true`. В очередь попадают только ранее привязанные файлы без оставшихся ссылок. Сбой сохранения может оставить безопасную удерживающую ссылку, требующую сверки. Старые неучтённые файлы защищены. Публичное удаление требует `FILES_DELETE_ENABLED=true`, загрузившего пользователя, запись в проект и отсутствие ссылок; Timepost допускает новые файлы с полным учётом, включая неиспользованные загрузки до первой привязки. Нельзя освобождать ссылки до commit транзакции владельца.

Приватный `GET /api/v1/files/{id}/thumbnail` создаёт WebP до 512×512 для фото. Чтение поддерживает один `Range: bytes=...` (206/416). Доступ и SHA-256 исходника проверяются полностью. Исходник пока скачивается целиком: Range уменьшает ответ клиенту, но не трафик провайдера. Миниатюры генерируются без постоянного кеша; постеры видео не реализованы.

Ответы содержат проверенный `X-Request-Id` и `Server-Timing: app`; корреляция передаётся в Accounts и Projects. `HTTP_REQUEST_LOG_ENABLED=true` включает логи маршрута, статуса и длительности без токенов и query. Одновременные скачивания и миниатюры ограничены четырьмя на экземпляр API; при занятости ответ 429.

Файлы, загруженные до миграции учёта ссылок, защищены даже после первой регистрации: на них могут ссылаться старые посты. Для их очистки нужна полная проверенная миграция всех ссылок.

После пересборки `make test-references` проверяет защиту ссылок на автономном PostgreSQL. Проверка создаёт только собственные метаданные без байтов и удаляет эти записи.

## Языки, темы и оформление

В строках есть «Предпросмотр»: фото/GIF, видео и распознанное аудио открываются в модальном окне с браузерным плеером. Фон, крестик и Escape закрывают окно, отменяют загрузку, останавливают воспроизведение и освобождают Blob URL. SVG и HTML не отображаются. Перед загрузкой проверяются имена на всех страницах; при совпадении можно принять суффикс или оставить прежнее имя. Это предложение UI: серверные UUID предотвращают перезапись, включая параллельные загрузки. Блоки появляются при входе в область просмотра; настройка уменьшения анимации учитывается.

По умолчанию UI открывается на английском; доступны русский и испанский. Закреплённый хедер содержит светлую, тёмную и системную темы. В localStorage сохраняются только эти настройки; ключ доступа остаётся в памяти вкладки.

`npm run icons:generate` пересоздаёт PNG 16–1024 px, SVG/ICO favicon, Apple touch icon, maskable-иконку, изображение для соцсетей и `public/manifest.webmanifest`. Исходник — `assets/branding/icon.svg`, браузерные ресурсы — `public/icons/`, TypeScript UI — `public/*.ts`. `npm run build` компилирует модули и копирует ресурсы в `dist/public/`. Service worker с версией по содержимому сборки кэширует только публичную оболочку UI. API и приватные файлы требуют сервера. [Безопасность развёртывания](SECURITY.md).

Выбор файла оформлен SVG-кнопкой с видимым фокусом клавиатуры. Закреплённый хедер скрывается при прокрутке вниз и возвращается при движении вверх или фокусе клавиатуры. Секции появляются один раз при входе в экран; режим уменьшения движения отключает анимацию и оставляет их видимыми. Полоса прокрутки соответствует светлой/тёмной теме (градиент в Chromium, однотонный цвет в Firefox). Футер содержит контакты разработчика и ссылку на репозиторий. Обработчик прокрутки пассивный, обновления ограничены кадрами, наблюдение за секцией прекращается после её появления.

## PWA и дополнительные форматы

Manifest перечисляет все PNG-размеры 16–1024 px и maskable-иконку. Браузер выбирает подходящий размер; весь набор не загружается автоматически. Worker заранее кэширует только публичную оболочку и основные иконки. API, запросы с Authorization, query, загрузка и приватное содержимое исключены. Обновление ждёт закрытия старых вкладок и удаляет только прежние кэши оболочки Files.

После первого успешного открытия онлайн интерфейс открывается без сети. Уведомление отключает серверные действия; офлайн-очереди загрузок и локальной копии библиотеки нет. Для внешнего запуска нужен HTTPS; loopback подходит для локальной разработки. [Документация Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers).

При `FILES_GENERIC_ENABLED=true` (по умолчанию автономно) аудио, анимированные GIF, SVG и произвольные файлы сохраняются с исходными байтами и именем, но выдаются как `application/octet-stream` для скачивания. SVG не исполняется на странице. Лимит вложений — 10 МиБ; проигрыватель, превью и проверка формата для них не добавлены. JPEG/PNG/WebP и MP4/WebM проходят отдельную проверку; для видео лимит 100 МиБ. Возможность хранения не означает поддержку публикации формата в соцсеть.
